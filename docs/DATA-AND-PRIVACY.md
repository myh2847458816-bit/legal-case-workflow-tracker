# 数据与隐私说明

## 一句话结论

法律案件流程台账是本地单机应用，不会自动上传案件数据；但它保存的主台账、恢复点和导出文件都是**明文文件**，拿到文件的人可以直接读取其中内容。

## 保存了什么

`case-tracker-data.json` 可包含：

- 案件名称、案号、客户、办理机关、承办人和案件备注。
- 流程快照、任务状态、计划办理日和办理备注。
- 案件关键日期、条件流程适用状态和最近操作。
- 用户创建或从案件保存的个人模板。

完整台账备份包含上述数据，可以在另一台电脑恢复。CSV 案件清单只包含适合查看与统计的案件摘要，不能恢复完整流程。

## 默认位置

| 系统 | 主台账默认位置 |
| --- | --- |
| Windows | `%APPDATA%\破产案件流程台账\case-tracker-data.json` |
| macOS | `~/Library/Application Support/破产案件流程台账/case-tracker-data.json` |

数据目录仍沿用早期“破产案件流程台账”名称，是为了让从旧版升级的用户能自动找到原有案件，并不表示新版只支持破产案件。

恢复点位于同一数据目录下的 `backups/`。用户手动导出的备份和清单保存在选择的位置。应用内的“数据与备份”页面可显示当前主台账路径。

## 不会自动发生的事

- 不会创建用户账号或远程数据库。
- 不会自动把台账上传到项目维护者。
- 不会自动把数据同步到 GitHub。
- 不会自动把备份发送到网盘或邮箱。

如果数据目录、桌面、文档或下载文件夹被操作系统或第三方软件同步，台账可能由该第三方软件上传；这不是本应用自带的同步功能。

## 为什么使用明文本地文件

当前产品优先考虑普通用户的可用性、可恢复性与跨电脑迁移。不引入额外主密码、密钥托管或与操作系统绑定的新加密数据，可以避免因忘记密码或更换电脑而无法恢复台账。

这项取舍意味着安全边界是用户的电脑账户和存储设备，不是应用内的另一层密码。

## 使用真实案件数据前的建议

1. 启用 Windows 登录密码与 BitLocker，或 macOS 登录密码与 FileVault。
2. 不在共享电脑、公共账户或无磁盘加密的 U 盘上保存台账。
3. 定期导出完整台账备份，保存到另一个可信且受保护的位置。
4. 在备份或恢复前核对文件来源，不导入来历不明的 JSON 文件。
5. 设备转让、维修或退役前，依照机构制度处理台账、恢复点和导出文件。

## 参与项目时的脱敏规则

不要将真实台账或对真实截图做简单打码后提交到 GitHub。需要复现问题时，请从空台账开始，使用虚构的当事人、案号、日期、金额和备注重新构造最小样例。
